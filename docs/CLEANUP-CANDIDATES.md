# Cleanup Candidates

Files and folders present in the working tree that are no longer needed, or that should not be there
at all. Reviewed 28 September 2026 against `main`.

Each entry states whether it is **tracked in Git** — that determines whether removing it needs a
commit or just a local delete.

---

## A. Delete — safe, no dependants

| Path | Tracked | Size | Why it can go |
| --- | --- | --- | --- |
| `analyzer-full.html` | No (gitignored) | 64 KB | Regenerated by `npm run scan` on demand. Already in `.gitignore` — it is local residue. |
| `braces.json` | No (gitignored) | 20 KB | Artefact of a one-off brace-balancing exercise. Already gitignored. |
| `braces-worklist.txt` | No (gitignored) | 8 KB | Same exercise. Already gitignored. |
| `CodeAnalyzerReport.html` | **Yes** | 64 KB | A generated scan report committed to the repository. Duplicates `code-analyzer-reports/FullCodeAnalyzerReport.html`. Generated artefacts do not belong in source control — they go stale and inflate diffs. |
| `force-app/main/default/lwc/peCrudStrip/` | **Yes** | 4 files | Not referenced by any template, tab or permission set. Superseded by `peCrudChips`, which `peListbox` actually uses. |
| `force-app/main/default/lwc/peGettingStarted/` | **Yes** | 4 files | Not referenced by any template or tab. The `Getting_Started` tab points at `gettingStarted`, not this. Duplicate of a component that already shipped. |
| `destructive/` | No (gitignored) | 12 KB | Byte-identical to `destructive-p3/` apart from line endings and a BOM. One of the two is redundant. Keep `destructive-p3/` (tracked) and delete `destructive/`. |

### Commands

```powershell
# Untracked local residue — just delete
Remove-Item analyzer-full.html, braces.json, braces-worklist.txt -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force destructive

# Tracked — remove and commit
git rm CodeAnalyzerReport.html
git rm -r force-app/main/default/lwc/peCrudStrip
git rm -r force-app/main/default/lwc/peGettingStarted
git commit -m "chore: remove generated report and two unreferenced LWC bundles"
```

> **Before deleting either LWC bundle**, run a last confirmation across the whole tree:
> ```powershell
> Select-String -Path force-app -Pattern "peCrudStrip|pe-crud-strip|peGettingStarted|pe-getting-started" -Recurse
> ```
> If either appears anywhere other than its own folder, stop and investigate.
>
> Because these are packaged components, add both to `destructive-p3/destructiveChanges.xml` — a 2GP
> package version cannot simply drop a component under `ancestorVersion: HIGHEST` without a
> deprecation path.

## E. Hygiene Notes

- `.gitignore` contains a duplicated Code Analyzer block — `analyzer-*.html`, `analyzer-*.json` and
  `appexchange.json` each appear twice, and `CodeAnalyzerReport.html` is commented out three times.
  A tidied version is supplied in this patch.
- `package.json` still carries the scaffolding identity: `"name": "salesforce-app"`,
  `"description": "Salesforce App"`, `"version": "1.0.0"`. Worth aligning with the product name and
  the package version.
- `README.md` was the stock Salesforce DX template and described none of this product. Replaced in
  this patch.
- Line endings are mixed across the tree — some files CRLF, some LF, some with a BOM. A
  `.gitattributes` with `* text=auto eol=lf` (and `*.png binary`) would settle it, though it produces
  one large normalising commit.
